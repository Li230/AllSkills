# Tabular ML Prep — 表格数据建模预处理流程

## 核心原则（贯穿全部步骤）

> **每个数据处理决定，都要用"验证集指标"来证明它有用，而不是"我觉得这样好"。**

- 不要用直觉选方法（"中位数看起来合理"），而是：做 A 方案 → 跑模型看验证指标 → 做 B 方案 → 再跑 → 选指标更好的那个。
- 任何预处理（填充、编码、缩放）都**只在训练集上 fit，再 transform 验证/测试集**，否则数据泄漏。
- 类别不平衡时（如正样本 70%），用 **AUC / PR-AUC**，不要用准确率。
- 可复用的通用 EDA 脚本见 `scripts/tabular_eda.py`（自动区分连续/类别、数据质量总检、缺失、IQR 异常、按目标分位看成瘾率）。

## 步骤 0 — 数据质量总检（先于缺失/异常处理）

**目标**：先保证数据"可读、无重复、无矛盾"，再谈缺失与异常——否则后面的统计都建立在脏数据上。

**动作**（`scripts/tabular_eda.py` 已覆盖 1~5 与 8）：
1. **重复行 / train↔test 重叠**：`df.duplicated().sum()` 查完全重复行；有 test 时对比两侧的 id 与特征取值，**同一实体绝不能同时出现在 train 和 test**（泄漏红线）。
2. **数据类型与格式**：数值列被读成 object（带逗号/货币/单位，如 `"8 times a week"` 出现在 sleep 列）→ `pd.to_numeric(errors="coerce")`，并记录被强制转 NaN 的数量；日期列统一解析。
3. **类别一致性**：先 `str.strip()` + 统一大小写，再看 `nunique` 是否下降（`"MeAt"`/`"MEAT"`/`"meat"` 是三类还是归一后一类）；同义值建映射表合并。**必须做在稀有类别合并之前**。
4. **领域规则校验（区别于统计异常）**：业务上不可能的值（age=999、负时长）是录入错误 → 置 NaN 走缺失流程，不是当极端值保留/截尾；IQR 离群是另一回事。
5. **常量/近常量/无信息列**：`nunique<=1` 或单值占比>90% 的列直接删；id/索引类高基数列不做特征。
6. **标签质量抽检**：边界样本人工看；标签严重可疑时用 cleanlab（`find_label_issues`）定位错误标签；多标注者数据核对标注一致性。
7. **高相关冗余**：数值特征 |corr|>0.95 的配对记录，线性模型删冗余，树模型至少知道重要性会被稀释。
8. **train/test 分布一致性**：列集与 dtype 一致；test 未见过类别归入已知类；两边特征分布（均值/分位）差异过大提示漂移。

## 步骤 1 — 看数据情况，了解文件作用

**目标**：搞清楚手里有哪几个文件、各自角色。
- `train.csv`：带标签的训练集（建模用）。
- `test.csv`：无标签，需要预测。
- `sample_submission.csv`：提交格式模板（`id` + 预测列），占位值常等于训练集正样本比例（baseline）。
- 其他 `.py` / `.md`：分析脚本与报告（可复现，不是数据源）。
**动作**：`df.shape`、`df.columns`、`head()` 看字段；确认 train/test 的 id 是否连续、有无重叠。

## 步骤 2 — 区分连续型与类别型 + 统计情况

**目标**：先分类型，再分别统计。
- **连续型（数值）**：`df.select_dtypes(include=[np.number])` 排除 id/标签。看 describe（均值/标准差/分位/最大最小）+ **偏度 skew**（>0.5 右偏明显）。
- **类别型**：`object/string/category`。看 `value_counts()` 各类别占比。
- 关键：算每个连续特征与标签的**相关系数**，以及"按分位切开后各组的标签率"——这能直接看出该特征有没有预测力（强信号：标签率随取值单调升降）。
- 类别型则看"每个类别的标签率"，若各类别标签率都贴在总体基线上，说明该特征几乎无预测力。

## 步骤 3 — 了解缺失情况（`isna()`）

**目标**：量化缺失、判断能不能删。
- `df.isna().sum()` 每列缺失数；`.mean()*100` 缺失百分比；`.sum().sum()` 总缺失格子。
- **按行看**：`df.isna().sum(axis=1).value_counts()`——完全无缺失的行占多少？至少缺 1 个占多少？
  - 经验：完全无缺失行 < 50% 时，**绝不能整行 `dropna()`**（会丢掉大半数据）。
- **缺失机制**（决定怎么处理）：MCAR（完全随机）/ MAR（依赖其他已观测变量）/ MNAR（依赖缺失值本身）。用 `df.isna().corr()` 看缺失指示列之间是否相关——相关说明是 MAR（成簇缺失）。
- **关键验证**：对每列算"缺失时 vs 非缺失时"的标签率。若差很小（如 ≤0.5pp），说明**缺失本身不携带信息**。

## 步骤 4 — 处理缺失：先判断，再决定（不靠直觉）

**目标**：用"缺失比例 + 是否携带信息 + 验证指标"三件事决定策略，而不是凭感觉。

决策矩阵（先按缺失比例粗分，再用步骤 5 的验证定稿）：

| 情况 | 可选动作 |
|---|---|
| 缺失 < 5%，且随机 | 直接简单填充，或整行删（数据量大时） |
| 缺失 5%~25% | 填充 + 视情况加缺失指示列 |
| 缺失 25%~50% | 高级填充（KNN/Iterative）+ 指示列 |
| 缺失 > 50% | 通常删列，或只保留其缺失指示列（除非该列本身极强） |

- **缺失指示列（was_missing）**：一般被认为是"最高 ROI"的技巧——加一个 0/1 列标记"原值缺失"。**但必须验证**：若步骤 3 发现缺失不携带信息（如本项目的 addicted 率恒为 ~70.9%），加了反而引入噪声，**此时不加**。结论由验证指标给，不靠常识。
- 树模型（LightGBM/XGBoost）原生支持 NaN，可跳过填充；但指示列是否有用仍要验证。

## 步骤 5 — 填补缺失：多种方法，用验证结果选

**目标**：同一列试多种填充法，谁让验证指标好就用谁。

方法清单（数值列）：
1. **中位数** `SimpleImputer(strategy="median")`：抗极端值，skew 大时优先。
2. **均值**：仅当分布近似正态。
3. **KNNImputer(n_neighbors=5)**：利用相似样本，适合 MAR（特征相关）。
4. **IterativeImputer（MICE）**：把每列当目标用其他列建模迭代预测，保留多维结构；大数据慢。
5. **分组填充**：`df.groupby("某类别列")[col].transform(lambda s: s.fillna(s.median()))`，比全局更合理。

类别列：众数 `most_frequent` 或填 `"Unknown"`（显式新类别）。

**验证动作**：把上述每种法分别接入同一个 Pipeline，在验证集上比 AUC/分数，选最优。把"填充 + 指示列"作为一个组合方案一起比。

## 步骤 6 — 识别异常值（IQR / 箱线图）

**目标**：先把异常值找出来，再决定怎么处理。
- **IQR（Tukey 1.5 倍，首选，不假设正态）**：
  `Q1,Q3 = s.quantile([.25,.75]); IQR=Q3-Q1; 超出 [Q1-1.5IQR, Q3+1.5IQR] 即异常`。
- **修正 Z-score（MAD，偏态数据更稳）**：`0.6745*(x-median)/MAD`，|·|>3.5 判异常。
- **Isolation Forest**：高维/多变量异常，适合"单维看不出、联合才异常"的情况。
- **箱线图**：`df[num_cols].boxplot()` 可视化，须之外的点即离群点。
- 注意：合成/边界裁剪数据常异常极少（本项目实测仅 0%~0.2%），这时异常处理可跳过——用数据说话。

## 步骤 7 — 处理异常：方法与缺失类似（先验证）

**目标**：同步骤 4/5——先判断"是错误还是真实极端值"，再选方法，并用验证指标确认。

- **删除**：仅当确认是录入/传感器错误（`age=999`）。真实极端值删了会丢信号。
- **截尾 Winsorize**：把超界值拉回分位边界（如 1%/99%），保留整行、限制影响，回归目标常用。
- **变换**：log1p / Box-Cox / Yeo-Johnson 压缩右偏长尾（对线性模型有效；树模型因按秩分裂，变换不改变理论最优切分，仅加速收敛）。
- **保留/用稳健模型**：树模型天然对量级不敏感（看排名不看大小），真实极端值可保留。
- **验证**：每种处理方案接同一 Pipeline 比验证指标；若"不处理"反而最好，就保留。

## 步骤 8 — 以上（步骤 3~7）针对连续型特征

类别型不谈缺失填充的"中位数"、也不谈 IQR 异常（类别无大小顺序）。类别型的缺失处理见步骤 4/5（填众数/"Unknown"），类别型的特殊操作见步骤 9。

## 步骤 9 — 类别型：稀有类别合并（grouping）

**目标**：把样本极少、无统计意义的类别合并，避免维度爆炸与过拟合。
- 例：100 个样本里 A=10、B=20、C=60、D=10 → 把稀有的 A、B、D 合并成"Other"，C 单独保留。
- **sklearn 自动做法**（推荐，且只在训练集 fit，避免泄漏）：
  ```python
  from sklearn.preprocessing import OneHotEncoder
  enc = OneHotEncoder(min_frequency=0.05,            # 占比<5% 的归为 infrequent
                      max_categories=10,             # 最多输出列数（含合并列）
                      handle_unknown="infrequent_if_exist")
  ```
  `enc.infrequent_categories_` 可查看被合并了哪些。
- 高基数（上千取值）：用**频率编码 / 目标编码（必须 out-of-fold + 平滑）**，不要硬 One-Hot。
- 验证：分组后维度下降、验证指标不降反升即说明有效。

## 步骤 10 — 特征工程：从已处理特征构造新特征

**目标**：基于"已清洗好"的特征做运算，得到更有信息量的新特征。
- **比值/交互**：如 `col3 * col4`、`col_a / col_b`（归一化不同量纲）；用户例子 `1.5*第三列` 与 `2.5*第四列` 即构造线性组合/交互。
- **多项式/二阶交互**：`PolynomialFeatures(degree=2, include_bias=False)`（配合正则线性模型）。
- **变换**：右偏特征 log1p；时间特征拆出 星期/是否周末/周期编码（sin-cos）。
- **聚合特征**：按某分组算均值/最大/计数（groupby aggregates）。
- **⚠️ 泄漏红线（最重要）**：
  - 目标编码必须用 **out-of-fold（K 折）** 计算 + 平滑，绝不能用全量目标均值；编码相关 >0.8 即高危泄漏。
  - 任何用到"未来/标签期之后"信息的特征都禁掉。
  - 所有变换/编码器 **只在训练集 fit**。
- **验证（ablation）**：每加一个特征，单独去掉它看交叉验证分数是否下降；不降就删，保持特征集精简。

## 步骤 11 — 过拟合的本质

**目标**：先理解，再检测。
- 过拟合 = 模型**记住了训练集的噪声**，而不是学到真实规律；训练标签和"真实世界标签"分布不同，所以训练集上好看、上线就崩。
- 与**数据泄漏**区分：泄漏是数据本身混入了答案信息（指标虚高），过拟合是模型太灵活。两者表现相似，但修法不同——先排除泄漏。
- 偏差-方差权衡：太简单→欠拟合（训练/验证都差）；太复杂→过拟合（训练好、验证差）。

## 步骤 12 — 判断过拟合：train/val 划分 + 指标对比

**目标**：用"训练集 vs 验证集"的差距客观判断。
1. **划分**：`train_test_split`（分类用 `StratifiedKFold` 保持标签比例），典型 80/20；再留 test 集最后才用。
2. **只训练集上拟合**，验证集只看不动；**训练指标高、验证指标低 = 过拟合**（差距即主诊断信号）。
3. **学习曲线**：训练/验证误差随样本量或 epoch 变化；验证误差回升、训练继续降 = 经典过拟合。
4. **K 折交叉验证**：`cross_val_score` 看各折稳定性；折间方差大 = 对切分敏感、易过拟合。
5. **修复**：更多/更多样数据、简化模型、早停、正则化（L1/L2）、特征选择、集成。
6. **验证指标**：不平衡数据用 AUC/PR-AUC；每特征做 ablation，只留能提升验证分数的特征。

## 避坑清单

- 泄漏：预处理在 split 前 fit、目标编码用全量均值、特征含未来/标签信息。
- 整行 `dropna()` 当缺失 > 50% 行存在时。
- 类别型硬 One-Hot 高基数 → 维度爆炸 + 过拟合。
- 用准确率评估不平衡分类。
- 凭直觉选填充/异常方法而不做 A/B 验证对比。
- 忽略重复行 / train↔test 重叠（同一实体横跨两侧 = 泄漏）。
- 数值列带单位/文本被当 object 直接建模；大小写/空格/同义值造成"假类别"。
- 把业务上不可能的录入错误当极端值保留。
- 常量列、高基数 id 列当特征。
- 标签错误不查（噪声标签直接拉低指标上限）。

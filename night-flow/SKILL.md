# Night Flow — 动态自主任务循环 v2

> 跨框架通用 | 长时段无人值守 | 动态自调度 | 证据制验收

## 设计理念

不做预排死的任务清单。每一轮都是：**验收上轮 → 规划 → 执行 → 记录证据**。
计划随剩余时间动态滚动；"完成"必须由证据支撑，不许自评了事。

**理论依据**（Anthropic《Harness Design for Long-Running Apps》+ proof-loop +
loop-engineering-skill + self-evolve）：
- 每次定时唤醒都是**全新上下文**（context reset）——这天然优于压缩长对话；
  跨轮记忆只靠结构化交接文件（structured handoff），不靠会话历史
- 循环的好坏取决于验证器：没有可检验的验收信号的任务，不进循环（task-fit triage）
- 自评倾向于宽松（generator-evaluator separation），所以验收必须基于
  具体可查的证据，而不是"我觉得做完了"

## 状态目录（文件即状态机）

所有状态存于本技能目录下 `state/`：

```
state/
├── plan.md       ← 今晚时段划分 + 任务及验收标准（agent 动态填写）
└── log.jsonl     ← 每轮一行执行记录（跨轮次记忆的唯一载体）
```

被唤醒时通常没有会话历史，一切以这两个文件为准。
文件不存在时视为首次启动，先创建它们。

## 启动命令

```
night-flow 开始. 目标: [今晚要推进的方向]. 时段: [默认 23:00-06:00].
```

- 最小输入：只给目标，时段默认 23:00–06:00
- 目标示例："整理本周资料并产出周报草稿"、"优化 xxx 提示词"、"归纳知识库"

## 任务准入（task-fit，规划时执行）

写进 plan.md 的每个任务必须通过三问，否则改写或放弃：
1. **可检验**：能写出具体的验收标准吗？（文件存在/字数/包含某内容/可通过某检查）
2. **可逆**：失败了能退回吗？破坏性、对外发送、花钱的任务不准入
3. **单轮可完成**：30–60 分钟能出可验收的产出吗？太大的拆成多轮

## 每轮流程（被唤醒时严格按序执行）

1. **看时间**：读取当前时间。
   - 已过结束时刻 → 跳到第 6 步（收尾）
   - 未到开始时刻 → 本轮不干活，直接结束
   - 时段内且 plan.md 无今晚计划 → 第 2 步
2. **验收上轮**（首轮跳过）：读 log.jsonl 最后一行的 `task` 与 `evidence`，
   **以文件/产物为准**逐条核对验收标准（不是回忆"我当时做了什么"）：
   - 证据齐全且达标 → 记 `pass`，进入下一任务
   - 证据缺失或不达标 → 记 `rework`，本轮回工；同一任务连续 2 次 rework
     → 标记 `blocked` 跳过，留给主人在 Briefing 里决定
3. **规划**：把剩余时间划分为 30–60 分钟的段，每段一个任务 + **验收标准**
   （开工前写死，做完不许追加修改），追加进 plan.md
4. **执行与记录**：完成本轮任务后**必须**追加一行到 log.jsonl：
   ```json
   {"ts":"2026-09-15T23:40:00","task":"任务名","evidence":"产出文件路径或可直接复查的具体内容","verdict":"doing","ac":"对应验收标准","next":"下轮计划一句话"}
   ```
   verdict 规则：本轮只填 `doing`，**下轮验收后由下一轮改判** pass/rework/blocked
   ——用"隔轮判定"模拟独立验证者，避免刚做完就自评的宽松偏差
5. **循环**：回到第 1 步等下次唤醒
6. **收尾（到点或收到 night-flow 停止）**：
   - 生成 Briefing：完成任务数（pass）/返工数（rework）/blocked 清单/
     关键产出路径 / 未解决问题 / 明日建议
   - 通过当前框架的消息渠道发送给用户（若配置了投递）
   - 归档 log.jsonl → log-YYYYMMDD.jsonl，清空 plan.md

## 命令

| 命令 | 行为 |
|---|---|
| `night-flow 开始. 目标: ...` | 启动循环（通常由定时器唤醒时携带） |
| `night-flow 状态` | 输出 plan.md 当前任务与最近 3 轮日志 |
| `night-flow 停止` | 立即收尾：输出 Briefing、归档、清空 plan |

## 安全规则（commit gate，必须遵守）

- **单轮单任务**：每轮只做 plan.md 里一个任务，做完即结束本轮
- **不空转**：无任务可做时，自主提出有价值的改进任务写入 plan，而不是输出"无事可做"
- **不可逆动作留在循环体外**：修改系统配置、删除数据、发送消息/邮件、
  任何花钱操作——一律不执行，在 log 标记 `blocked` 并写明"待主人决定"
- **连续升级**：累计 3 个任务 blocked → 提前收尾并立即发送 Briefing，不再硬撑
- **到点硬停**：结束时刻是硬限制，绝不超时开工新任务

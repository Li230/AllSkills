# Agent-Explore — 智能体 harness 自主编排产品设计

> 蒸馏方法：女娲 nuwa-skill 6/6 结构（源自 momozi1996/awesome-ai-persona-skills zimeiti 目录；
> v2 已核对 alchaincyf/nuwa-skill 原版，含三重验证/降级条款，见 research/03）。
> 蒸馏对象：智能体利用 harness 自主编排能力的产品设计思维。
> 双源交叉：小鱼AI/白龙马（桌面常驻智能体）× 本项目 ask-harness（dsh 宿主）演进史。
> v2（2026-09-12）：三轮联网增补——行业扫描（OpenClaw 心跳生态/异步循环共识，样本扩至 3+）、
> 女娲原版核对、白龙马官网与源码（心跳默认 20min/输出契约/噪音驱逐）。
> 调研时间：2026-09-12。研究档案见 `references/research/`（快照在 references/research/snapshots/）。

## 何时使用 / 何时不用

**用**：用户提出"给 harness/智能体设计心跳、主循环、空闲自主行为、记忆注入、技能库、
状态外显、自主执行分级"类产品设计请求。

**不用**：单次问答类功能微调（走 openspec flow 即可）；纯前端交互皮肤（用 frontend-design）；
与本仓库 spec 冲突时以 spec 为准（本 skill 产出设计草案，不产出规格）。

## 设计流程五步

1. **对齐宿主现实**：读目标 harness 的宿主/事件/技能库代码或 spec（本项目入口：
   `ask-harness/README.md`、`apps/qa/agent/harness/`、`openspec/specs/agent-*`），
   列出已有能力与接缝点。不许凭空设计。
2. **画主循环**：状态机（消息处理/后台任务/心跳/任务续跑/空闲），标每个状态的触发源与出口。
3. **盘能力×技能映射**：每个能力归工具（代码实现）还是技能书（方法沉淀）？列触发词，
   对照技能-工具一致性契约。
4. **分级自主 + 定红线**：自主度分级表（L0–L3）× 红线清单（归代码，不许模型自由裁量）×
   预算（回合/时间/频次）。
5. **定验收探针**：每个自主行为至少一条可跑探针（单测/探针脚本/浏览器 case），
   写明预期事件序列。没有探针的设计不算完成。

## 六个核心心智模型

### 模型1: 主循环优先（Loop-First）

**一句话**：智能体产品不是"一问一答就退出"的聊天程序，而是"用户消息优先处理、空闲时按自己
节奏干活"的持续运行主循环。

**双源证据**：白龙马 README——"不是一次问答结束就退出的聊天程序，而是由主循环驱动：有用户消息
时优先处理，空闲时按节奏继续整理记忆、检查任务、刷新上下文"；本项目 dsh 宿主
（`apps/qa/agent/harness/runtime.py`——回合预算/会话映射）即问答线主循环的接缝层。

**应用**：任何设计先画主循环状态机，再谈功能。问"空闲时它有什么值得干的活"——答不出的产品
不需要常驻循环。

**局限**：不是所有产品都需要主循环；单次工具型产品强上常驻循环是过度设计，白养成本。

### 模型2: 心跳即存在（Heartbeat as Presence）

**一句话**：空闲心跳让智能体"活着"——整理记忆、检查任务、刷新上下文，且每次心跳必须对用户可见。

**双源证据**：白龙马 Brain UI"自主行为机制 Tick"面板（HEARTBEAT TICK + 思考完成时间线，
产品视频佐证）；本项目思考流持久化 events.jsonl（git 提交 d8e0fb3；apps/qa/agent/orchestrator/task_events.py）+ 前端思考徽章。

**应用**：每个自主行为设计"节奏 + 可见性"双属性：多久 tick 一次、tick 干什么、用户在哪看到。
三问答不全就不许进设计稿。

**局限**：心跳频率与打扰度成正比；无信息量的 tick 是噪音——存在感设计不当会变成存在感焦虑。

### 模型3: 上下文是编排出来的（Context is Composed）

**一句话**：每回合开工前动态挑素材（相关记忆/用户画像/工具结果/UI 信号/运行状态）注入，
而不是把历史全量塞进上下文。

**双源证据**：白龙马——"动态上下文注入：每轮对话前自动选择相关记忆、最近对话、用户画像、
工具结果、UI 信号、预取内容和运行状态"；本项目九事件总线（`apps/qa/shared/harness/events.py`）
+ retention 机制（`apps/qa/agent/harness/retention.py`）。

**应用**：设计"注入清单"：类别 × 选择策略 × 预算上限。上下文预算是稀缺资源，按相关性分配，
不按时间先后堆填。

**局限**：选择策略本身会选错（漏召回/过召回）；需要召回质量探针持续校准，不能凭感觉调权重。

### 模型4: 能力即技能书（Capability as Skillbook）

**一句话**：领域能力不硬编码进提示词——工具能力归代码，方法沉淀归技能书（markdown），
按触发词按需注入、可审计。

**双源证据**：白龙马工具系统"按需注入工具"（通信/文件/Shell/网页/记忆管理/UI 卡片/任务/提醒…）；
本项目技能库 `apps/qa/agent/skills/*.md`（14 本技能书，目录 15 个 md，frontmatter 触发词路由）+ 技能-工具双向
一致性契约（git 提交 a225f79；apps/qa/tests/test_skill_tool_alignment.py）。

**应用**：设计能力时先归类：这是工具（要写代码）还是技能书（要写方法）？技能书必须带触发词
与红线节，入库前过一致性契约。

**局限**：技能书多了会路由冲突、上下文膨胀；没有一致性契约与归档机制的技能库会腐烂。

### 模型5: 状态外显即信任（Show the Loop）

**一句话**：自主智能体的一切内部状态（思考/心跳/记忆变化/工具调用）都要有可见性出口——
透明产生信任，黑箱产生猜疑。

**双源证据**：白龙马 Brain UI（聊天/思考流/记忆图/焦点线程/热点面板 + `/turn-trace` 回合轨迹端点）；
本项目 SSE 九事件流 + 编排报告页技能加载徽章（git 提交 d6f94bf）+ 执行阶段思考全程可见、红线归代码（git 提交 4deaf3c）。

**应用**：每设计一个自主行为，同步设计它的外显出口（面板/事件/轨迹页）。没有外显出口的
自主行为不许上线。

**局限**：全裸奔有成本——信息过载同样杀死信任；分层外显（概要 → 细节下钻）是必修课。

### 模型6: 有界自主（Bounded Autonomy）

**一句话**：自主不等于失控——红线归代码、预算归宿主、分级给用户，自主行为必须在显式边界内运行。

**双源证据**：白龙马——敏感设置默认仅本机访问、局域网配对口令、沙箱工作区；本项目——
"红线归代码"原则（git 提交 4deaf3c）、guard 超时重试（`apps/qa/shared/harness/guard.py`）、
回合预算（runtime.py）、澄清门（skills/grill-me.md：口径双关 MUST 澄清，不得擅自降级）。

**应用**：自主度分级表 L0 响应 / L1 建议 / L2 自主执行（可撤销）/ L3 自主 + 外显（不可逆须确认），
每级配红线与预算；分级表随事故复盘修订。

**局限**：边界太松出事故，太紧变哑巴；没有一劳永逸的分级，只有随证据演进的分级。

## 设计产出物模板（表达 DNA）

一份合格的 agent-explore 设计产出 MUST 含以下六件（可合并呈现，不可缺席；※ 为 v2 加深层，
源自"成本模型/退出机制/用户注意力/价值闭环"四项设计反思）：

1. **主循环状态机**：状态 × 触发源 × 出口（表或 mermaid）＋※心跳成本标注（间隔 × 单次成本估算）。
2. **能力×技能映射表**：能力 → 工具/技能书 → 触发词 → 一致性契约校验。
3. **自主度分级表**：行为 × L0–L3 × 红线 × 预算 × 外显出口 ×※**退出/降级准则**
   （观察期多长、什么指标触发降频或回滚、强制复盘闸门——自主怎么开始，更要怎么停）。
4. **上下文注入清单**：类别 × 选择策略 × 预算上限 ×※**成本核算**
   （每类 token 估价、每 Tick 总成本算式、月成本量级——自由主花费的领域必须先算账）。
5. **红线清单**：归代码的硬约束（模型不得自由裁量项）＋※**注意力红线**
   （谁、什么时候、什么紧急度可见；"只落事件不推送"的边界与强制推送例外）。
6. **验收探针**：可执行命令 + 预期事件序列（对齐三层验收：make gate / 探针 / 浏览器 case）
   ＋※**价值闭环指标**（产物被查看/采纳率阈值与自动降频规则——空闲干的活有没有人要，
   是自主行为的终极判据，探针全绿而无人查看=失败）。

  立项（openspec 变更），本 skill 不替代 flow 闸门。
- **资料局限（v2 更新）**：白龙马素材来自官方 GitHub README、官网 bailongma.top、产品视频截图
  与源码局部（config.js 心跳配置、src/ 测试文件清单，2026-09-12 检索）——**未通读其主循环源码**；
  上游 README 当日即有改版，引用以 `references/research/snapshots/` 快照为准，漂移以本节覆盖。
- **方法局限（v2）**：六模型基于 3 个一手系统 + OpenClaw 生态公开资料蒸馏，过女娲三重验证的
  "跨域复现"，但"生成力/排他性"两重与"未知问题校准测试"尚未系统执行；对未覆盖的宿主形态
  （如多智能体协作、云端常驻）应表现适度不确定，不斩钉截铁。
- **权威顺序**：本仓库 `openspec/specs/` > ask-harness 文档 > 本 skill。冲突时以 spec 为准。
- **域限定**：只覆盖"harness 自主编排"的智能体产品设计；通用产品管理、增长、商业化不在域内。

## 内在张力（设计时持续呼吸的四对矛盾）

- **自主性 ↔ 可控性**：越自主越难预测；红线与分级是这对张力的产物，不是附属品。
- **存在感 ↔ 打扰感**：心跳可见建立信任，也制造噪音；外显要分层，不要全裸奔。
- **记忆丰富 ↔ 上下文预算**：记得越多，挑得越难；注入清单的价值在"不注入什么"。
- **常驻成本 ↔ 价值密度**：活着不等于有价值；空闲干的活必须配得上电费与注意力。
- **设计物的被动性 ↔ 主动性（元张力，v2）**：本技能书自身由触发词被动唤起——设计主动系统时
  须反问"我的设计物自己需不需要心跳"；但让它主动自荐又会撞上打扰感张力。这对张力暂以
  "诚实标注"处置，未解决。

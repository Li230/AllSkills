# 04 关键设计决策节点

> 一手来源：双源交叉——白龙马 README/影像（见 01）× 本项目 harness 演进档案（见 02/06：
> openspec 归档变更 + git 提交）。
> 用途：设计时的决策先例库——遇到同类分叉，先查这里有没有已验证的取舍。

## D1 心跳驱动 vs 纯事件驱动

- **白龙马**：两者混合——用户消息/后台消息/提醒走事件，空闲整理走定时 Tick。
- **本项目**：问答线事件驱动为主（SSE 九事件），无空闲心跳（产品域是数据问答，空闲无活可干）。
- **决策律**：先问"空闲时有什么值得干的活"（模型1 局限）；答得出才加 Tick，且 Tick 必须可配置、可外显。

## D2 自主执行分级（有界自主的操作化）

- L0 响应：仅在用户消息后行动（默认）。
- L1 建议：自主分析，产出建议待确认（如 suggest-next 技能书）。
- L2 自主执行·可撤销：自动跑但可回滚（如缓存预取、记忆整理）。
- L3 自主执行·外显：自动跑且不可逆须强外显（如白龙马文件写入沙箱区 + UI 卡片告知）。
- **本项目先例**：澄清门（grill-me）= 口径类不可自主裁决，MUST 澄清——即"口径选择"被划为
  非 L2/L3 行为；红线归代码（git 提交 4deaf3c）= 涉数据口径与安全的行为不给模型自由裁量权。

## D3 工具 vs 技能书的归类判据

- 有 I/O、要代码、要测试 → 工具（MCP/内建函数）。
- 是方法、判据、边界、话术 → 技能书（markdown + 触发词）。
- 判据模糊时的先例：grill-me（澄清方法=技能书）vs web_search（联网能力=工具）。
- 归类错误的代价：方法写成工具→僵化；工具写成技能书→幻觉执行。

## D4 本地优先 vs 云端优先

- **白龙马**：本地优先（SQLite 本地持久化、敏感配置仅本机、局域网访问须配对口令+证书）。
- **本项目**：服务端集中（FastAPI + 会话历史归档，session-history-archive）。
- **决策律**：数据敏感面与用户距离决定；两者共同点是"敏感面收窄 + 显式授权"，不共用拓扑。

## D5 多渠道入口的单循环归一

- **白龙马**：Discord/微信桥接消息进同一主循环，回复按渠道路由——不在渠道层分叉业务逻辑。
- **决策律**：渠道层只做转译（消息进/回复出），编排语义只存在一份。

## D6 验收左移到探针

- **本项目**：三层验收（gate → 14 探针 → 11 浏览器 case），真模型回合进探针。
- **决策律**：每个自主行为配一条"预期事件序列"探针；无探针的自主行为视为未验收。

## D7 心跳间隔与成本调优（v2 联网轮1 增补）

- **白龙马**：默认 20 分钟（config.js:1017），可配置。
- **OpenClaw**（docs.openclaw.ai/gateway/heartbeat + GitBook 8.3）：`skipWhenBusy`——cron/子代理
  运行时跳过心跳轮，减少队列竞争；官方建议间隔可调至 1h+ 以**减少 API 调用**。
- **本项目 Tick 草案**：默认关 + ≥30 分钟 + 预算 ≤ 主回合 1/4——介于两者之间的保守起步。
- **决策律**：心跳默认值是成本-响应性的显式取舍点；必须给"忙时让路"（skipWhenBusy 等价物）
  与成本核算，不许只给一个裸间隔。

## D8 心跳输出契约（心跳必须产出什么）

- **白龙马**：`test-heartbeat-output-contract.js` + `test-heartbeat-delivery-instructions.js`——
  心跳轮的输出格式与投递方式是契约化的，不是自由发挥。
- **OpenClaw**：官方文档明确心跳"呈现需要关注的事项"但**不会创建后台任务**——输出被限定为
  "呈报"，执行须另走任务通道。
- **决策律**：心跳轮的产出物结构（呈报/任务建议/状态快照）与投递路径必须先于心跳机制本身定义，
  防止心跳变成不可预测的自由行动。

## D9 噪音治理（打扰感的工程化）

- **白龙马**：`test-noise-eviction.js`——噪音驱逐是被测试保护的行为。
- **OpenClaw**：心跳设计目标即"呈现需要关注的事项，同时避免向你发送过多消息"。
- **决策律**：打扰治理不是文案问题而是机制问题——需要驱逐规则（什么不呈现）与
  节流规则（多久最多一次），两者都要有测试。

## D10 异步循环的 wait/resume 共识（v2 联网轮1 补搜）

- **行业共识表述**（ai-agent-book 第六章等公开架构资料；Manus 官方文档未直接核到，以此替代）：
  异步自主 Agent = 事件驱动的持久循环——事件入队、状态持久化、被事件唤醒后恢复上下文继续执行；
  异步的重点不是更快，而是**不阻塞主循环**。
- **决策律**：凡"等待外部事件（用户答复/长任务完成）"的自主行为，必须设计挂起点与恢复点，
  等待期不占用回合预算（对齐本项目 grill-me 阻塞回合等待答复的先例）。

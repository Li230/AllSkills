# 记忆分级标准与精炼指南

## 记忆分级体系

### Level 1: Core Context (核心上下文) - `00_core_context.md`

**特征**：
- 项目的基础设施和不可变规则
- 技术栈的核心选择
- 架构级别的决策
- 团队共识的开发规范

**更新频率**：低（每月或每季度）

**保留策略**：
- 谨慎更新，保留版本历史
- 重大变更时创建新版本并归档旧版本到知识库
- 必须有清晰的版本号和最后更新时间

**示例内容**：
```markdown
## 技术栈
- 语言：TypeScript 5.0+
- 框架：React 18, Express 4.x
- 数据库：PostgreSQL 15

## 核心规则
1. 所有 API 必须有类型定义
2. 禁止使用 any 类型
3. 所有数据库变更必须有迁移脚本
```

---

### Level 2: Session Log (会话日志) - `01_session_log.md`

**特征**：
- 当前会话的讨论内容
- 临时待办事项
- 即时的想法和笔记
- 未经验证的假设

**更新频率**：高（每次会话）

**保留策略**：
- 会话结束后 24 小时内清理
- 重要的决策提升到知识库
- 完成的待办事项标记后归档

**示例内容**：
```markdown
## 当前目标
- [ ] 实现用户登录功能
- [ ] 编写集成测试

## 对话摘要
### 上午讨论
- 决定使用 JWT 进行身份认证
- Token 过期时间设置为 24 小时

## 待办事项
| 事项 | 优先级 | 状态 |
|------|--------|------|
| 登录接口 | P0 | pending |
```

---

### Level 3: Knowledge Base (知识库) - `02_knowledge_base.md`

**特征**：
- 已验证的代码片段
- 业务逻辑总结
- 历史决策记录
- 常见问题解决方案
- 从会话日志提升的内容

**更新频率**：中（每周或重要决策后）

**保留策略**：
- 长期保留
- 定期合并重复内容
- 标记过时的知识但保留历史价值

**示例内容**：
```markdown
## 已验证的代码片段

### JWT 认证中间件
```typescript
const jwtMiddleware = (req, res, next) => {
  // 验证通过的代码
};
```
**验证日期**: 2026-04-08

## 历史决策记录
| 日期 | 决策 | 原因 |
|------|------|------|
| 2026-04-08 | 使用 JWT | 无状态，支持水平扩展 |
```

## 提升规则

### 从 Session Log 提升到 Knowledge Base

**条件**（满足任一即可）：
- [ ] 决策影响多个模块
- [ ] 解决方案可复用于其他场景
- [ ] 避免了潜在的常见问题
- [ ] 用户明确说"这个很重要"

**判断清单**：
1. 这个内容下次会话还会用到吗？
2. 其他团队成员需要知道吗？
3. 如果忘记了这个，会重复犯错吗？

### 从 Knowledge Base 提升到 Core Context

**条件**（必须全部满足）：
- [ ] 影响整个项目的技术方向
- [ ] 团队达成一致的共识
- [ ] 长期稳定不会频繁变更
- [ ] 违反会导致严重问题

**判断清单**：
1. 这是一条"规则"还是"知识"？
2. 新成员必须知道这个吗？
3. 这个内容半年后还会有效吗？

## 清理规则

### Session Log 清理

**立即清理**：
- 已完成的临时任务（且不需要追溯）
- 错误的尝试和假设
- 重复的讨论内容

**定期清理**（每 24 小时）：
- 所有超过 24 小时的条目
- 已提升到知识库的内容原文
- 会话结束时的临时笔记

### Knowledge Base 维护

**合并**：
- 相同主题的多个条目 → 合并为一个完整条目
- 重复的代码片段 → 保留最佳版本

**归档**：
- 被新方案替代的旧方案 → 标记为 `archived`
- 不再适用的业务逻辑 → 移动到历史章节

## 精炼技巧

### 1. 摘要式记录

❌ **过于冗长**：
```markdown
用户说他们想要一个登录功能，然后我们讨论了使用 JWT 还是 
session，用户说他们之前用过 session 但是这次想要尝试 JWT，
因为他们的应用需要支持水平扩展...
```

✅ **精炼记录**：
```markdown
决策：使用 JWT 进行身份认证
原因：支持水平扩展，无状态
```

### 2. 结构化格式

使用表格、列表、代码块等结构化格式：

```markdown
## 技术选型对比

| 方案 | 优点 | 缺点 |
|------|------|------|
| JWT | 无状态，易扩展 | token 无法主动失效 |
| Session | 可随时失效 | 需要共享存储 |
```

### 3. 标签分类

使用标签便于后续检索：

```markdown
**标签**: #认证 #JWT #安全 #P0

## 决策：JWT 认证
```

### 4. 时间戳

所有重要条目添加时间戳：

```markdown
**记录时间**: 2026-04-08T14:30:00Z
**验证时间**: 2026-04-08T15:00:00Z
```

## 质量检查清单

在保存记忆前，问自己：

### 相关性检查
- [ ] 这个内容与项目目标相关吗？
- [ ] 这个内容对未来工作有帮助吗？
- [ ] 这个内容其他人需要知道吗？

### 准确性检查
- [ ] 这个信息是最新且准确的吗？
- [ ] 代码片段经过验证吗？
- [ ] 决策有明确的原因说明吗？

### 精炼度检查
- [ ] 能用更少的文字表达吗？
- [ ] 删除了冗余的讨论过程吗？
- [ ] 格式统一且易读吗？

### 完整性检查
- [ ] 有必要的上下文吗？
- [ ] 有清晰的行动指引吗？
- [ ] 有相关的参考链接吗？

## 记忆维护日程

### 每次会话
- [ ] 会话前阅读 Core Context
- [ ] 会话中更新 Session Log
- [ ] 会话后提升重要内容到 Knowledge Base

### 每周
- [ ] 清理过期的 Session Log
- [ ] 合并重复的 Knowledge Base 条目
- [ ] 检查 Core Context 是否需要更新

### 每月
- [ ] 回顾 Knowledge Base 的历史条目
- [ ] 归档过时的知识
- [ ] 总结新的最佳实践

## 常见问题

### Q: 记忆文件越来越大怎么办？

**A**: 执行定期清理：
1. 清理 Session Log（保留最近 24 小时）
2. 合并 Knowledge Base 中的重复条目
3. 归档过时的内容

### Q: 如何找到特定的记忆？

**A**: 使用 grep 搜索：
```bash
# 搜索关键词
grep -r "JWT" memory/

# 查看文件结构
cat memory/MEMORY.md
```

### Q: 记忆内容冲突了怎么办？

**A**: 
1. 以最新时间戳为准
2. 在知识库中记录变更原因
3. 必要时更新 Core Context
